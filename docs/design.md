# Open Context Article Reader：独立博文理解 Skill 设计草案

**日期：** 2026-10-20

**状态：** 第一版设计基线；实际行为以 `SKILL.md` 和代表性测试结果为准

**仓库：** `apframework-studio/open-context-article-reader`

## 目标与定位

做一个可独立安装、调用的 Agent Skill，帮助读者理解**单篇博文或网络文章**：作者讨论的问题、中心观点、论证或操作路径、关键概念、证据与适用边界。输出优先帮助领域学习，而不只缩写原文。技术、商业、哲学文章都在范围内；类型列表可扩展。

Skill 不依赖 Open Context Forge 的 vault，也不负责采集队列、长期知识整理、文章写作或发布。未来可以把结果交给其他系统，但第一版不定义知识库读写接口。书籍、长篇系统课程和论文专门阅读流程另行设计；论文或书籍的短篇介绍文章仍可按博文处理。

## 理解对象的三个维度

对每篇文章分别判断，避免把学科、写作目的和质量混成单一分类。

| 维度 | 示例 | 对阅读方法的影响 |
| --- | --- | --- |
| 领域 | 技术、商业、哲学、跨领域 | 决定要补哪些先备概念，以及验证来源的种类 |
| 文章功能 | 观点论证、教程、经验复盘、产品/方案介绍、评论、信息汇编 | 决定重点检查论证、步骤、决策背景或事实来源 |
| 信息状态 | 背景充分/不足，证据充分/薄弱，可复现/不可复现，时效性高/低 | 决定可得出的结论强度与补充调研范围 |

不强迫每篇文章落入唯一类别；混合型文章可以说明主要功能与次要功能。质量判断须指出具体缺口，不给无解释的总分。

## 输入与输出契约

初版输入：用户给出的单篇文章 URL、全文、Markdown 或本地文本文件。若只有 URL，先取得足够的正文，确认标题、作者/日期（若可得）、正文完整性与引用上下文。无法读取正文时说明原因并请求正文，不依据标题或搜索摘要代写分析。阅读语言按用户要求；未指定时跟随对话语言。

默认输出应能回答以下问题，顺序和篇幅随文章类型调整：

1. **文章定位：** 来源、作者、日期（若可得）、领域、文章功能、读到的范围与完整性。
2. **研究/讨论对象：** 文章试图解释或解决什么问题；为什么作者认为这个问题值得讨论。
3. **中心观点与结构：** 结论是什么，各部分如何推进；对于教程则交代目标、前提、步骤和预期结果。
4. **推理与依据：** 关键主张、证据或例子、隐藏前提、反例与适用条件；区分作者报告的事实和作者的解释。
5. **概念学习：** 读者理解文章所需的少量关键概念、相互关系、先备知识缺口，以及可帮助自我解释的问题。
6. **判断与下一步：** 哪些观点得到原文支持，哪些仍未证实；必要时给出值得核对的外部问题、不同视角或实践验证路径。

每个关键判断标明其来源层级：**原文明确陈述、基于原文的推断、外部资料、尚不确定**。能定位时引用原文章节或短摘录；对外部信息给出可核查来源。缺失的背景保持为缺失，不补写成作者意图。

不固定输出一个冗长表格。用户只想快速判断文章是否值得读时，可以给压缩版；用户要求深读、学习或评估时展开相关部分。

## 方法论：按文章任务选用分析视角

这些方法提供可解释的分析问题，不构成一套已被整体实证验证的“科学评分算法”。实际输出应以文章内容和用户目的为主，避免套模板。

| 视角 | 在本 Skill 中的用途 | 不适用或需要谨慎的情况 |
| --- | --- | --- |
| 篇章/修辞结构分析 | 找出背景、问题、方法、例证、转折、结论之间的关系 | 碎片化、叙事型文章不必强行还原标准结构 |
| Toulmin 论证要素 | 对观点文识别主张、依据、从依据到主张的理由、限定和反驳 | 教程、清单、产品说明不必逐段做论证拆解 |
| 文本表征与情境模型 | 区分文章实际写了什么，以及读者为理解主题需要构建的背景模型 | 外部背景不得被当成文章原有内容 |
| 自我解释与检索练习 | 把概念关系转为少量理解检查题或应用问题 | 不要把测试题当作主输出，除非用户要学习练习 |

技术教程侧重机制、前提、可复现条件及版本/环境；商业分析侧重目标、激励、数据与替代解释；哲学论述侧重概念定义、论证形式、反例与立场边界。以上只是选镜头的规则，不是三个硬编码流程。

## 外部调研

对时效性、专业术语、关键引用、显著缺失的背景或高度争议的结论，进行**针对性**外部核对。先提出具体核对问题，再找原始/权威资料；呈现外部发现如何支持、修正或挑战原文。外部研究不能替作者补全未表达的论证，也不能让分析从“理解这篇文章”漂移成主题综述。若用户明确只要原文分析，则不主动扩展外部研究。

知识库不是第一版依赖；将来若用户显式提供知识库，可以作为读者先备背景或对照材料，并明确区分其内容与原文、公开资料。

## 第一版边界与验收

- 不做书籍级分章节阅读、自动知识库分类/写入、写作/发布、批量 RSS 监控。
- 不以文章长度或领域决定固定模式名称；根据文章功能、证据状态和用户目标调整分析深度。
- 不把“作者没有说明”推断成“作者主张”；不把案例自动推广为一般规律。
- URL 获取失败、正文不完整、作者或日期缺失时明确报告限制。

至少用四类真实样例检验：技术教程、商业观点文、哲学论述、背景或证据不足的低质量文章。再测混合类型、只有 URL 且无法读取、用户只要简版，以及不该触发本 Skill 的书籍请求。检查输出能否准确复述文章而不臆测，能否根据类型切换分析视角，外部资料是否明确分层，是否能指出具体而可核查的缺口。

## 已定与待定

- URL/正文/文件的第一版具体格式、附件读取能力，以目标运行环境实际可用工具为准。
- 是否提供显式的“快速理解/深入分析”调用方式，以及默认输出篇幅，先用真实文章试读后定。
- 仓库自身内容已采用 MIT 协议；外链文章及其他第三方资料不因此变为 MIT 授权。新增贡献方式或示例文章时，仍需核对引用范围与授权。

## 参考

- [Mann 与 Thompson：修辞结构理论](https://www.benjamins.com/catalog/iprapip.1.1.03tho)——分析文本部分之间的功能关系。
- [Toulmin：The Uses of Argument](https://www.cambridge.org/core/books/the-uses-of-argument/26CF801BC12004587B66778297D5567C)——论证结构视角。
- [Kintsch：构建—整合的篇章理解模型](https://pubmed.ncbi.nlm.nih.gov/3375398/)——区分文本信息与读者整合背景后的理解。
- [Chi 等：自我解释与理解](https://www.sciencedirect.com/science/article/pii/0364021394900167)、[Roediger 与 Karpicke：检索练习](https://pubmed.ncbi.nlm.nih.gov/16507066/)——为可选的学习检查问题提供依据；不能据此断言本 Skill 的完整流程已获验证。
- [OpenAI：Build skills](https://developers.openai.com/plugins/build/skills)——独立 Skill 可仅由说明和资源组成；`SKILL.md` 必需，其他资源按需添加，并用代表性请求测试触发与输出。
- [DeepRead](https://github.com/xiehuan123/dsh-deepread)——同类方案参考；本项目聚焦单篇博文，不沿用其图书场景或模式划分。
